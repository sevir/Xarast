# Per-file limits for `cargo xtask export-check --limits` over the .xar
# corpus exported at 72 dpi over the paper (phase 11 T11.6.2, T11.6.3).
# Every other file must stay under the default 4/255 mean |difference|.
#
# Format: <stem> <svg|pdf> <max mean |difference| in 1/255>
# Each limit is the value measured on 2026-09-24 plus ~15 % headroom, with
# the reason the file differs. Lowering a limit after a fix is welcome;
# raising one needs the reason written here. Numbers: docs/memory/export.md.

# The TextDesigns files carry the original's own rendering of the text as
# a placed bitmap under the live text (SimpleText 183x128 px drawn at
# 88x62, 2.1x; TextJust 652x1243 px, 4.2x). Since XARA-US-0052 our PNG
# minifies it with a footprint-widened tent (1-2x) or a linear-light mip
# pyramid (beyond 2x); resvg filters the SVG <image> without mip levels,
# as our old sampler did. The SVG bytes are unchanged; only the PNG
# reference moved: SimpleText 2.03 -> 6.20, TextJust 2.19 -> 9.17
# (measured 2026-09-24). A filter policy, not geometry.
SimpleText svg 7.2
TextJust svg 10.6

# Small text (5-9 px glyphs at 72 dpi). Since T11.4.7 (XARA-T-0228) PDF
# text is live text in embedded subset fonts, so the viewers rasterise the
# glyphs with their own font engines (FreeType in Poppler, Ghostscript's
# own), which paint small text darker than our coverage antialiasing -
# more so than the filled outlines PDF used to carry (TextJust 13.7 ->
# 18.4, SimpleText 8.6 -> 13.3, measured 2026-09-24). Stripping the
# TrueType hinting tables changes nothing measurable (Poppler does not
# hint). At 8x the glyphs land where our export draws them (SimpleText
# 3.4/255 with Ghostscript); `--text outlines` gives back the outline
# numbers. This is the renderers' text policy, not geometry.
